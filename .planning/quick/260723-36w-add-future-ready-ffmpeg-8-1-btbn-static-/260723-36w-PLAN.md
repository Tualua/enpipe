<objective>
Add an opt-in, future-ready FFmpeg 8.1 (BtbN static GPL) build to the devcontainer image as a SEPARATE, side-by-side install that does NOT replace the base image's system ffmpeg 6.1.1. The 8.1 build brings the corruption-immune `av1_qsv`/`hevc_qsv` encoders (per-component surface pools, immune to the cross-process reference-surface aliasing that plagues concurrent qsvencc — see `.planning/debug/scene-chunk-frame-mismatch.md`) plus the `dovi_rpu` bitstream filter for Dolby Vision RPU passthrough that 6.1.1 lacks.

Purpose: make a modern QSV/DV-capable ffmpeg available for opt-in use without disturbing the verified system media stack.
Output: one new Dockerfile RUN layer installing to `/opt/ffmpeg-8.1/` with `ffmpeg-8.1`/`ffprobe-8.1` on PATH, plus a non-fatal post-create self-check.

CRITICAL: The container is NOT rebuilt in this session (no docker / no GPU here). This is a Dockerfile + post-create.sh change only. The SUMMARY must state the image is unbuilt/unverified-here and the host rebuilds later, with a rebuild checklist.
</objective>

The comment MUST explain, in Russian: (1) this is an OPT-IN, side-by-side FFmpeg 8.1 that does NOT replace system ffmpeg 6.1.1 — installed to a separate path; (2) WHY it matters — ffmpeg `av1_qsv` is the corruption-immune encode path (qsvencc concurrent 10-bit+B-frame encode aliases reference surfaces cross-process; ffmpeg's per-component surface pools are immune — reference `.planning/debug/scene-chunk-frame-mismatch.md`), and 8.1 additionally brings the `dovi_rpu` bitstream filter for DV RPU passthrough that 6.1.1 cannot do; (3) the PIN TRADEOFF — BtbN's `latest` is a MOVING rolling release: the asset NAME is stable but its CONTENTS change daily, so builds are non-deterministic. State that we deliberately accept this (option a) for consistency with how qsvencc/dovi_tool already fetch "latest GitHub release", and that NO SHA256 verification is added because a moving tag has no stable published checksum (note this explicitly rather than silently omitting it).

Implement the RUN following the existing `set -eux; ... curl -fsSL ...; tmpd="$(mktemp -d)"; ... rm -rf ...` idiom (plain curl — no github_token secret):
- Download the stable asset URL `https://github.com/BtbN/FFmpeg-Builds/releases/download/latest/ffmpeg-n8.1-latest-linux64-gpl-8.1.tar.xz` to a temp file.
- Extract with `tar -xJf` into a `mktemp -d` dir (xz-utils already present).
- Install ONLY the `bin/` binaries — `ffmpeg` and `ffprobe` (skip `ffplay`) — to `/opt/ffmpeg-8.1/bin/` via `install -m0755 "$(find "$tmpd" -type f -name ffmpeg | head -1)" /opt/ffmpeg-8.1/bin/ffmpeg` and the ffprobe equivalent (create the dir with `mkdir -p /opt/ffmpeg-8.1/bin` first).
- Expose on PATH as opt-in alternatives via `ln -sf /opt/ffmpeg-8.1/bin/ffmpeg /usr/local/bin/ffmpeg-8.1` and the `ffprobe-8.1` equivalent — do NOT touch `/usr/local/bin/ffmpeg` or the system `ffmpeg`.
- Sanity-echo `/usr/local/bin/ffmpeg-8.1 -hide_banner -version | head -1` inside the RUN (build-time smoke check).
- Clean up the temp dir and downloaded tarball in the final `rm -rf`.
