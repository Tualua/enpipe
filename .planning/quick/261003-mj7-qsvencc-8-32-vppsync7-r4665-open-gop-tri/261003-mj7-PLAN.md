<objective>
Move enpipe to the Tualua/QSVEnc fork 8.32-vppsync7 (r4665) and drop the
open-GOP hard refusal added in quick 261003-lpo. vppsync7 adds patch #6:
"Fix --trim after --seek on open-GOP HEVC: RASL no longer counted into trim
offset; --avsw now drops RADL at start like --avhw so both select the same
frames". The orchestrator verified on A380 with r4665 (og1 x265 open-gop with 4
RASL per CRA, og0 closed; --avhw and --avsw): `--seek 2.002 --trim 4:13` gives
first frame 52 / 10 frames, `--trim 0:9` gives 48 / 10 frames (r4663 gave 48 / 6).
The owner of the fork work confirms that RASL and RADL are cut correctly in both
decoders and that no compensation is needed.

Purpose: since the global revision gate (run before every encode, fail-closed,
no bypass) now guarantees the fix, the per-source refusal only blocks valid
sources (x265's default is open-gop=1, so most real HEVC encodes). Open-GOP
sources go back into hardware tests as a POSITIVE content check.

Output: repinned images + gate r4665, guard code and its tests removed, positive
open-GOP/RADL hardware tests, HDR10 test on default x265 GOP, docs/debug files
updated, full hardware module green.
</objective>

<design_decisions>
D-A Remove the probe entirely (`probe_leading_frames`, `count_leading_after_keyframes`,
`_ffprobe_packet_lines`, `LEADING_PROBE_PACKETS`, the open-GOP paragraph in the
keyframes.py module docstring). Justification: (1) the only consumer was the
refusal in run_encode; (2) `ensure_qsvencc_fixed()` runs on every encode, has no
bypass and is fail-closed, so a binary with the trim-offset defect cannot reach
chunk encoding at all — a second per-source guard keyed to the same defect is
dead weight and costs one ffprobe per run; (3) there is no other concrete use
(nothing else needs N). The hardware tests still need a "this source really has
leading pictures" precondition — that goes into a small TEST-LOCAL helper (full
ffprobe packet scan; synthetic sources are 12 s, so cost is irrelevant), not src/.

D-B No compensation, no change to compute_chunk_seek_trim / kf_before / fmt_seek /
keyframe_table*. `kf_before` stays (used by compute_chunk_seek_trim and tests);
pipeline.py just stops importing it if unused after the removal (ruff decides).

D-C RADL variant IS added: cheap. Verified in this planning session with
ffmpeg libx265 320x180, `keyint=48:min-keyint=48:scenecut=0:bframes=4:open-gop=0:radl=2`:
packets after the IDR at 2.002 in decode order are 1.960, 1.918 (pts < K) — i.e.
2 RADL pictures in front of every IDR except frame 0. Patch #6 explicitly covers
RADL (avsw now drops RADL like avhw), so both leading-picture kinds are tested.

D-D test_hdr10 goes back to x265's default GOP (remove `:open-gop=0` and its
comment): the earlier failure of test_hdr10 (debug session, chunk 2, K=250,
N=2) proves its source cuts mid-GOP after CRAs with RASL, so it now covers
open-GOP + HDR10 together. Closed-GOP coverage stays in test_chunk_content_closed_gop.

D-E Synthetic mid-GOP layout gains one cut EXACTLY on a keyframe that has leading
pictures (`--trim 0:..` after CRA/IDR_W_RADL — the case the orchestrator probed
as `--trim 0:9` -> 48). Scene lengths change from 70/80/70/68 to 70/74/76/68:
cuts at 70 (mid-GOP), 144 (= keyframe 144), 220 (mid-GOP), 288 frames total,
keyframes 0..240 every 48; included scenes [0,70),[70,144),[144,220) end
<= last keyframe 240. Preconditions (pytest.fail, not assert): >= 1 included
scene starts mid-GOP, >= 1 included scene starts on a non-zero keyframe, and
(open/radl only) the used seek keyframes != 0 have leading pictures > 0.

D-F Gate refusal text keeps the three defects with their revisions:
45003f1/#308 (< r4634), `--seek` one GOP late (< r4663, vppsync6), open-GOP
`--trim` shifted by −N RASL (< r4665, vppsync7). QSVENCC_METRICS_MIN_REV keeps
following QSVENCC_MIN_REV.
