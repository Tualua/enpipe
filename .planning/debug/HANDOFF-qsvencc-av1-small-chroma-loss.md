# HANDOFF: QSV AV1 «съедает» цвет мелких тусклых деталей (энкодер не даёт управлять квантованием цветности)

**Дата:** 2026-10-05
**Откуда:** enpipe. Оператор заметил это глазами на реальном HDR10-эпизоде, затем замеры
**Кому:** соседний проект с форком Tualua/QSVEnc
**Версия:** QSVEncC 8.32 (r4665), форк `8.32-vppsync7`; Arc A380, iHD 26.3.2, libva 1.24; ffmpeg n9.0.2 (BtbN static)

> Это **не порча и не баг пайплайна**. Число кадров, выравнивание и яркость в порядке. Проблема в качестве: мелкие малонасыщенные цветные детали (красные точки в несколько пикселей на тёмном фоне) теряют 30–50% насыщенности. VMAF её **не видит**: он считается только по Y, поэтому кадр с явной потерей получает обычные 83–84.

---

## 1. Симптом на реальном материале

HDR10 PQ 3840×1600, 24 к/с, HEVC Main10. Серия E01, кадр 66490 (46:10.42), сцена [66489, 66663).

- В источнике видны небольшие красные элементы. В энкоде (enpipe, продакшен-argv, `--icq 23`) они почти серые.
- Средние метрики потерю прячут: PSNR U/V по кадру 54.9 / 55.6 дБ, крупные красные области сохраняют 98%.
- В блоках 32×32 px с мелкими деталями краснота (Cr−Cb относительно 512, 10 бит) падает с 41 до 9, с 45 до 15, с 38 до 12.

Перекодирование одной этой сцены, метрика «сохранность мелкого красного», медиана по блокам:

| Вариант | Кадр 0 (key) | Кадры 1..7 | Битрейт |
|---|---|---|---|
| `--icq 23` (продакшен) | 85% | 83–85% | 5.2 Мбит/с |
| `--tune default` / `psnr` вместо `perceptual` | выход побайтно тот же | — | 5.2 |
| `--icq 20` / `--icq 18` | 85% | 85% | 15.6 / 26.5 |
| `--icq 1` | **98%** | **86%** | 44.6 |
| `--gop-ref-dist 1` (только P), `--icq 20` | 89% | 85–88% | 25.5 |
| без `--b-pyramid` | выход побайтно тот же | — | 5.2 |
| `--avsw` вместо `--avhw` | как `--avhw` | — | 5.2 |

Что из этого видно:
- Декод не виноват: HEVC через QSV и программный декодер дают побайтно одинаковый кадр.
- **Keyframe** восстанавливает цвет при `--icq 1`, а **inter-кадры не восстанавливают** даже при `--icq 1` (86%). Похоже, режим блока выбирается по яркости, и цвет копируется из опорного кадра без поправки.
- Побочное: `--tune perceptual|default|psnr` и `--b-pyramid` при `--gop-ref-dist 6` на AV1 дают побайтно тот же выход. Возможно, эти параметры для AV1 вообще не доходят до драйвера. Это стоит проверить отдельно.

## 2. Минимальное воспроизведение на синтетике

Защищённого контента нет. 120 тусклых малонасыщенных красных квадратов 4/6/8 px на тёмном фоне, сдвиг на 12 px/с. Все команды проверены на A380 2026-10-05.

```bash
# источник: HEVC Main10, 3840x1600, 3 с
boxes=""; for i in $(seq 0 119); do x=$((120+(i%15)*245)); y=$((120+(i/15)*175)); sz=$((4+(i%3)*2))
  boxes="$boxes,drawbox=x=$x:y=$y:w=$sz:h=$sz:color=0x2C1818:t=fill"; done
ffmpeg -v error -y -f lavfi -i "color=c=0x161616:s=3960x1600:r=24:d=3,format=yuv444p$boxes,crop=3840:1600:x='t*12':y=0,format=yuv420p10le" \
  -c:v libx265 -preset fast -x265-params "crf=2:keyint=72:min-keyint=72:colorprim=bt2020:transfer=smpte2084:colormatrix=bt2020nc:log-level=error" \
  -pix_fmt yuv420p10le dim.mkv

# энкод тем же argv, что в enpipe (без HDR-флагов: в синтетике нет mastering-метаданных)
qsvencc --backend qsv --avhw -i dim.mkv -c av1 --icq 23 --qp-max 100 --output-depth 10 --profile main \
  --gop-len 300 --gop-ref-dist 6 --b-pyramid --tile-col 1 --tile-row 1 --tune perceptual --scenario-info archive \
  --avoid-idle-clock off --colorrange auto --colormatrix auto --colorprim auto --transfer auto --chromaloc auto -o dim.obu

python3 measure_red.py dim.mkv dim.obu 12     # скрипт приложен: HANDOFF-qsvencc-av1-small-chroma-loss.measure_red.py (numpy + ffmpeg)
```

`drawbox` здесь статичный, движение даёт `crop=x='t*12'`. В `drawbox` переменная `t` означает толщину рамки, а не время.

Результаты, медиана / худшие 10% блоков, 12 кадров:

| Энкодер | Сохранность мелкого красного | Размер |
|---|---|---|
| qsvencc AV1 `--icq 23` | **71% / 51%** | 20 КБ |
| qsvencc AV1 `--icq 18` | 89% / 79% | 20 КБ |
| qsvencc AV1 `--icq 10`, `--icq 1`, `--cqp 10` | 99% / 93% | 28 КБ |
| ffmpeg `av1_qsv -global_quality 23` | 69% / 48% (почти тот же выход) | 20 КБ |
| qsvencc HEVC `--icq 23` | 72% / 42% | 12 КБ |
| libx265 `-crf 22` | 88% / 70% | 32 КБ |
| libsvtav1 `-crf 30` | 61% / 32% (key 89%) | 16 КБ |

Вывод по синтетике: **это поведение медиадвижка Arc и драйвера iHD, а не код qsvencc**. ffmpeg `av1_qsv` ведёт себя так же, и HEVC QSV тоже. Синтетика воспроизводит только часть с квантованием цвета (лечится снижением QP). Вторую часть, когда inter-кадры не восстанавливаются даже при `--icq 1`, на синтетике получить пока не удалось. Её стоит искать на реальном фрагменте (E01, сцена 549, есть у оператора локально).

Метрика (`measure_red.py`): «краснота» r = (Cr−512) − (Cb−512) в 10-битных отсчётах цветности. Берутся блоки 16×16 отсчётов цветности, в которых у источника от 3 до 20 точек с r > 30. Для каждого блока считается отношение средней красноты энкода к источнику, затем медиана и 10-й перцентиль по блокам. Фон и крупные цветные области в метрику не попадают.

## 3. Что хотелось бы от qsvencc / форка

1. **Квантование цветности для AV1.** В AV1 у кадра есть `delta_q_u_dc/ac` и `delta_q_v_dc/ac`. В VA-API у `VAEncPictureParameterBufferAV1` есть соответствующие поля (`u_dc_delta_q`, `u_ac_delta_q`, `v_dc_delta_q`, `v_ac_delta_q`; **проверить**). Вопросы:
   - даёт ли oneVPL или iHD их задать для AV1-энкода;
   - если да, можно ли вывести это в qsvencc параметром вроде `--chroma-qp-offset <int>` для AV1, а для HEVC через `pps_cb_qp_offset/pps_cr_qp_offset`.
   - **Ожидаемый эффект:** отрицательная дельта для U/V вернёт цвет мелких деталей ценой небольшой прибавки битрейта. Это гораздо дешевле, чем снижать ICQ для всего кадра (сейчас ×3–5 по битрейту ради +2–5 п.п.).
2. **Режим блока в inter-кадрах.** На реальном материале цвет не восстанавливается в inter-кадрах даже при `--icq 1`. Вопросы:
   - есть ли в oneVPL или VDENC параметры, которые влияют на учёт цветности при выборе skip/merge. Например, `mfxExtCodingOption3`, `mfxExtAV1BitstreamParam` или скрытые параметры iHD;
   - если такой параметр есть, его стоит вывести в qsvencc.
3. **Проверить, доходят ли `--tune` и `--b-pyramid` до AV1-энкода.** На реальной сцене выход побайтно одинаковый при `--tune perceptual|default|psnr`, а также с `--b-pyramid` и без него (при `--gop-ref-dist 6`).

## 4. Что ждёт enpipe

- Если появится параметр смещения QP цвета, enpipe проверит его на этой же синтетике и на сцене 549. Это будет сравнение сохранности мелкого красного, PSNR U/V и битрейта, после чего параметр можно будет добавить в argv чанка.
- До этого в enpipe ничего не меняем, качество цвета считается известным ограничением энкодера. В инструмент анализа кадров enpipe добавит проверку по U/V, чтобы такие кадры находились автоматически, а не только глазами.
