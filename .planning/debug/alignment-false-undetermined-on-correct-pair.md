## Resolution

root_cause: |
  Реализация ведёт себя в точности по записанным решениям (CONTEXT WR-09/CR-01/CR-02, правило (в)); это дизайн-пробел, а не расхождение кода с решением. Три слитых фактора:
  1) Набор «5->9» — следствие WR-09 (fd71364): «выровнено» замены склейки больше не заменяет итог цели, а добавляется в points голосом (точки 648, 57516, 71293), плюс закрывающие повторы сторон CR-02 (57234, 73546). Сами цели те же 5 (pick_points не менялся).
  2) Неопределённая склейка закрывается только повтором внутри СВОЕЙ сцены на фиксированной сетке align_retry_step=48 (вперёд, для start−1 — назад по предыдущей сцене). Для статичного кадра/короткой сцены сетка даёт 0–1 кандидата: склейка 0 (сцена 0..100 статична целиком, все кандидаты < 0.7 дБ), 75 (сцена 75..148: единственный кандидат 123 = 0.25 дБ, а 90/135 дали бы 3.16/3.07 дБ), 73498 (чёрный кадр start; предыдущая сцена 73426..73497 — все кандидаты ≈ 0.0 дБ).
  3) Общий лимит align_retry_max=3 тратится на замены, которые по WR-09 цель закрыть уже не могут (замена — всегда голос): у цели 0 две замены (101, 648) съели 2 из 3; у 73498 две замены (73426, 71293) оставили 1 попытку, ушедшую на start (73546), а prev (73449) не измерен вообще (хотя по кандидатам 73449..73486 он всё равно ≈ 0.0 дБ, т.е. в этом файле не помог бы).
  Итог: любая «неопределённая» склейка без закрывающего кадра внутри собственной сцены при правиле (в) = отказ, даже когда 7 из 9 точек aligned shift 0 с запасами до 43 дБ.
