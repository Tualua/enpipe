Новый leaf-пакет `src/enpipe/analysis/` — только чистые функции, ни одного subprocess:
метрики кадра на парах 10-битных YUV-плоскостей (MET-01..04), provisional-пороги как

НЕ в фазе: извлечение кадров и выравнивание (фаза 10), CLI `analyze`, кропы/PNG,
флаг «VMAF хорош, цвет плох» (фаза 11), скан по сценам и батч (фаза 12), калибровка и
сравнение энкодов (фаза 13). `encoding/`, `detection/`, `mkv/` не меняются ни в одной строке.

<decisions>
## Implementation Decisions

### Сохранность цвета мелких деталей (MET-01)
- **D-01:** Формула блока — как в прототипе: блок `16×16` отсчётов цветности (= 32×32 px при 4:2:0); блок берётся, если у источника 3..20 точек с `hypot(Cb−512, Cr−512) > 30`; значение блока = проекция `Σ(s·e)/Σ(s·s)` по этим точкам (s, e — векторы (Cb,Cr)−512 источника и энкода).
- **D-02:** Агрегат по кадру: медиана и p10 значений блоков (как в прототипе — на этой формуле получены приёмочные 71→88 % и 80→84 %) **плюс** дополнительное поле «отношение сумм» `Σ_всех блоков(s·e) / Σ_всех блоков(s·s)` (совет PITFALLS B5). Ранжирование/серьёзность — по p10.
- **D-03:** Минимум блоков `MIN_CHROMA_BLOCKS = 5` (provisional; так работал скан прототипа, нашедший кадр 66490). При `n_blocks < 5` результат — статус «нет мелких цветных деталей» (значения None, не число), `n_blocks` всё равно записывается; такой кадр не участвует в ранжировании по цвету.
- **D-04:** Проекцию НЕ обрезать: >1 (перенасыщение) и <0 (сдвиг оттенка) сохраняются как есть.
- **D-05:** Параметры отбора (размер блока 16, порог насыщенности 30, диапазон точек 3..20) — поля конфига с текущими значениями прототипа; пересмотр только в калибровке фазы 13.
- **D-06:** Возвращать координаты худшего блока в пикселях (понадобятся для кропа ×2 в фазе 11).

### Тайлы и худший тайл (MET-02, MET-03)
- **D-07:** Сетка тайлов — фиксированный размер в пикселях (стартово 256×256 по Y, 128×128 по цветности; константа конфига), не фиксированное число тайлов 8×4 как в прототипе. Границы тайлов чётные.
- **D-08:** Неполные края: остаток меньше половины тайла приклеивается к соседнему (последнему полному) тайлу, иначе считается отдельным тайлом. Ни один пиксель не теряется. Табличные тесты на неполные края (например, 1600 = 6×256 + 64 → остаток приклеен; 3840 = 15×256 → ровно).
- **D-09:** Худший тайл по цветности — по суммарному MSE U+V; для него пишутся PSNR U и PSNR V. Худший тайл по Y — отдельно. Глобальные PSNR Y/U/V по кадру — тоже.
- **D-10:** Сохранность детали по Y (энергия лапласиана энкод/источник) — глобально по кадру **и** минимум по тайлам (самый «замыленный» тайл, с координатами).
- **D-11:** Ниты (PQ EOTF, limited range `(Y−64)/876`, `max(p−c1, 0)`), средняя яркость и доля теней < 5 нит — как в прототипе; табличный тест на опорных кодах ST 2084.
- **D-12:** ΔE ITP (BT.2124): среднее и p99 по кадру; константы матриц BT.2100/BT.2124 сверить по стандарту при реализации (в исследовании не перепроверены).

### Источники кандидатов и слияние (CND-01, CND-02, CND-05)
- **D-13:** Из худшей сцены CSV qsvencc берётся один кадр — середина `start_frame + (end_frame − start_frame)//2`. Кадр/границы — из колонок CSV (`start_frame`, `end_frame`), не из `.scenes`.
- **D-14:** Худшие сцены CSV — объединение топ-N по `ssim_y` и топ-N по `psnr_y`; у кандидата записано, по какой колонке он попал (возможно обе). Пустые/nan значения в топ не попадают; если колонка целиком пустая — источник сообщает об этом (статус, не падение). Строка `ИТОГО` пропускается.
- **D-15:** Коллизии (кандидаты разных источников ближе `--min-gap`): сливаются в один кадр, выбранный по приоритету источника **ручной > VMAF > CSV > скан**; у итогового кандидата список ВСЕХ источников. Ручные `--frames` никогда не выбрасываются ни разносом, ни квотой.
- **D-16:** Дефолты: квота 2 кандидата на сцену, общий лимит `--top 40`. Без `.scenes` квота не применяется (только разнос и лимит). Результат детерминирован при равенствах (стабильная сортировка по кадру).

### Внешний VMAF (CND-04)
- **D-17:** Ридер принимает tsv/csv, колонку `vmaf`, десятичную запятую. Ожидаемое число кадров передаётся параметром (чистая функция; в фазе 10+ — из probe). При несовпадении длины или базе индекса ≠ 0 (колонка кадра начинается с 1 и т.п.) — файл отвергается с объяснением (например «база индекса 1, длина X ≠ Y»), без автосдвига. Отказ — статус источника в модели отчёта, остальные источники работают.

### Модель отчёта и report.json (RPT-01, MET-05)
- **D-18:** Ключи `report.json` — английский snake_case, совпадают с полями датаклассов; в корне `schema_version: 1`. Русский текст только в `report.md`/`index.html`.
- **D-19:** Неконечные числа: `+inf` → строка `"inf"` (PSNR идентичных тайлов, контроль «энкод против себя»), `nan` → `null`. JSON строгий (без `Infinity`/`NaN`), читается jq и браузером.
- **D-20:** Модель — полный каркас уже в фазе 9: метаданные запуска (версии инструментов — опционально), пороги с пометкой provisional, статус каждого источника кандидатов (включён / недоступен / отвергнут + причина), кандидаты с источниками, строки кадров (включая строки ошибок извлечения), сводка перцентилей (min, p1/p5/p10, медиана), опциональные поля под выравнивание и кропы. Фазы 10–11 только заполняют поля; `schema_version` не меняется.
- **D-21:** Golden-тест: фиксированная модель-фикстура → `report.json` сравнивается побайтно (`sort_keys`, фиксированный `indent`, `ensure_ascii=False`); md/html — снапшот структуры + `html.escape` на имени файла.

### Claude's Discretion
- Точные имена модулей/датаклассов (ориентир — ARCHITECTURE.md: `config.py`, `metrics.py`, `sources.py`/`candidates.py`, `report.py`; конфиг `AnalyzeConfig`).
- Парсинг `--frames` (список/диапазоны), формат чисел в md/html, внутреннее представление статуса источника.

- Хранить ли «сырые» значения цвета при `n_blocks < 5` в json для отладки (в ранжировании и в выводе как числа — нет).
- Выводить ли в фазе 9 `pairing.py` — по ARCHITECTURE он чистый, но требование ANL-02 в фазе 12; планировщик решает.

## Specific Ideas

- Порт из прототипа `vmaf_frames.py` (сохранён в `.planning/phases/09-analysis-core-readers/vmaf_frames.prototype.py`): `small_chroma`, `pq_nits`, `lap_energy`, `tile_psnr`, `psnr`, `read_vmaf`, `pick_worst` — без прямого `subprocess` и без модульных глобалов `GRID_X/GRID_Y/CHROMA_B` (поля конфига).
- Опорные тесты метрики цвета: энкод = источник → 1.0; точечная деталь ±100 в источнике, 0 в энкоде → ~0.0; нет блоков → статус «нет деталей», n=0; перенасыщение → >1 без обрезки.
- PSNR идентичных плоскостей → inf (в json `"inf"`).
- Ридер `.scenes` — свой regex в analysis + тест-сторож на совпадение с `encoding.scenes_io._SCENE_RE`; ридер CSV — тест-сторож round-trip через `encoding.metrics.write_metrics_csv` (inf/nan/None, `ИТОГО`).

## Existing Code Insights

### Reusable Assets
- `encoding/metrics.py::write_metrics_csv` — генератор CSV для round-trip теста ридера.
- `encoding/scenes_io._SCENE_RE` — эталон формата `.scenes` для теста-сторожа.
- `shared/logging` (`die`, `log`) — в чистом ядре не нужен; ядро не вызывает `die()`.

### Established Patterns
- `@dataclass(frozen=True)` для конфига и значений; `typing` (`List`, `Optional`, `Tuple`), `from __future__ import annotations` в каждом модуле.
- Русские docstring/комментарии/сообщения, английские идентификаторы; модульный docstring «зачем».
- Исключение `AnalysisError(RuntimeError)` с однострочным русским docstring.
- Чистый парсер + тонкая I/O-обёртка (как `mkv/ebml.py` + `encoding/keyframes.py`).
- ruff `F`, `E9`; без новых зависимостей (`uv.lock`/`pyproject.toml` без изменений).

### Integration Points
- `tests/unit/analysis/` — новый каталог быстрого тира (без subprocess).
- Пакет `analysis` импортирует только numpy/stdlib (и `encoding.*` лишь в тестах-сторожах); `encoding`/`detection` не импортируют `analysis`.

</code_context>
