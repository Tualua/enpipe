### Locked Decisions
- **D-01:** Формула блока — как в прототипе: блок `16×16` отсчётов цветности (= 32×32 px при 4:2:0); блок берётся, если у источника 3..20 точек с `hypot(Cb−512, Cr−512) > 30`; значение блока = проекция `Σ(s·e)/Σ(s·s)` по этим точкам (s, e — векторы (Cb,Cr)−512 источника и энкода).
- **D-02:** Агрегат по кадру: медиана и p10 значений блоков **плюс** поле «отношение сумм» `Σ_всех блоков(s·e) / Σ_всех блоков(s·s)`. Ранжирование/серьёзность — по p10.
- **D-03:** `MIN_CHROMA_BLOCKS = 5` (provisional). При `n_blocks < 5` — статус «нет мелких цветных деталей» (значения None, не число), `n_blocks` записывается; такой кадр не участвует в ранжировании по цвету.
- **D-04:** Проекцию НЕ обрезать: >1 и <0 сохраняются как есть.
- **D-05:** Параметры отбора (размер блока 16, порог насыщенности 30, диапазон точек 3..20) — поля конфига; пересмотр только в калибровке фазы 13.
- **D-06:** Возвращать координаты худшего блока в пикселях.
- **D-07:** Сетка тайлов — фиксированный размер в пикселях (стартово 256×256 по Y, 128×128 по цветности; константа конфига). Границы тайлов чётные.
- **D-08:** Неполные края: остаток меньше половины тайла приклеивается к последнему полному тайлу, иначе отдельный тайл. Ни один пиксель не теряется. Тесты: 1600 = 6×256 + 64 → приклеен; 3840 = 15×256 → ровно.
- **D-09:** Худший тайл по цветности — по суммарному MSE U+V; для него пишутся PSNR U и PSNR V. Худший по Y — отдельно. Глобальные PSNR Y/U/V — тоже.
- **D-10:** Сохранность детали по Y (энергия лапласиана энкод/источник) — глобально и минимум по тайлам (с координатами).
- **D-11:** Ниты (PQ EOTF, limited `(Y−64)/876`, `max(p−c1, 0)`), средняя яркость и доля теней < 5 нит; табличный тест на опорных кодах ST 2084.
- **D-12:** ΔE ITP (BT.2124): среднее и p99 по кадру; константы матриц BT.2100/BT.2124 сверить по стандарту при реализации.
- **D-13:** Из худшей сцены CSV берётся один кадр — `start_frame + (end_frame − start_frame)//2`. Кадр/границы — из колонок CSV, не из `.scenes`.
- **D-14:** Худшие сцены CSV — объединение топ-N по `ssim_y` и топ-N по `psnr_y`; у кандидата записано, по какой колонке (возможно обе). Пустые/nan в топ не попадают; пустая колонка целиком — статус, не падение. Строка `ИТОГО` пропускается.
- **D-15:** Коллизии (ближе `--min-gap`): сливаются в один кадр по приоритету **ручной > VMAF > CSV > скан**; у итогового кандидата список ВСЕХ источников. Ручные `--frames` никогда не выбрасываются ни разносом, ни квотой.
- **D-16:** Дефолты: квота 2 кандидата на сцену, общий лимит `--top 40`. Без `.scenes` квота не применяется. Детерминизм при равенствах (стабильная сортировка по кадру).
- **D-17:** Ридер VMAF: tsv/csv, колонка `vmaf`, десятичная запятая. Ожидаемое число кадров — параметр. Несовпадение длины или база индекса ≠ 0 → файл отвергается с объяснением, без автосдвига; статус источника в модели отчёта, остальные работают.
- **D-18:** Ключи `report.json` — английский snake_case, совпадают с полями датаклассов; в корне `schema_version: 1`. Русский текст только в md/html.
- **D-19:** `+inf` → `"inf"`, `nan` → `null`; JSON строгий (без `Infinity`/`NaN`).
- **D-20:** Модель — полный каркас уже в фазе 9: метаданные запуска, пороги с пометкой provisional, статус источников, кандидаты с источниками, строки кадров (включая строки ошибок), сводка перцентилей (min, p1/p5/p10, медиана), опциональные поля под выравнивание и кропы. ## Summary

Фаза — это порт готового прототипа (`vmaf_frames.prototype.py`) в чистый пакет `src/enpipe/analysis/` плюс три новых куска, которых в прототипе нет: ΔE ITP, сетка тайлов с неполными краями, модель отчёта с golden-json. Новых зависимостей нет (numpy 2.5.1 и stdlib уже в проекте; установленный numpy проверен: 2.5.1). Все решения зафиксированы в CONTEXT.md; исследовательская неопределённость сосредоточена в трёх местах: (1) числовые константы ITP/PQ (сверены), (2) формат реального CSV qsvencc (прочитан `write_metrics_csv`), (3) детали сериализации inf/nan.

Главные технические риски: тихая порча числа (деление на ноль в проекции цвета, `psnr=inf` в JSON, `nan`-контаминация ранжирования), память на 4K (float64 temporaries) и порядок слияния кандидатов при приоритетах и квоте. Всё закрывается маленькими чистыми функциями и табличными тестами.

**Primary recommendation:** пакет `analysis/` из 5 модулей (`config.py`, `metrics.py`, `tiles.py` (или внутри metrics), `sources.py`, `candidates.py`, `report.py`), метрики на `float32` с полосовой обработкой только для ITP/PQ (самые тяжёлые), все публичные значения — frozen dataclass с `None` вместо NaN там, где «нет данных», а `nan/inf` нормализуются ровно в одной функции `to_jsonable()`.

### Pattern 1: Статус вместо NaN (MET-01)
**What:** результат цвета — frozen dataclass `ChromaDetail(status, n_blocks, median, p10, ratio, worst_x, worst_y)`; `status ∈ {"ok","no_details"}`; при `no_details` числа `None`.
**When:** всегда при `n_blocks < cfg.min_chroma_blocks`. Прототип возвращал `nan` при `n==0` и числа при 1..4 — это то, что запрещает D-03.
```python
# Source: порт vmaf_frames.prototype.py::small_chroma + D-01..D-06
def small_chroma(su, sv, eu, ev, cfg) -> ChromaDetail:
    ...  # блоки B=cfg.chroma_block; для каждого блока: m = sat>cfg.sat_thr; if min<=m.sum()<=max: s,e по маске
    # знаменатель Σ(s·s) > 0 гарантирован: все точки маски имеют sat > 30
```
Векторизация: `H//B`, `W//B` полных блоков (края цветности, не кратные 16, в прототипе отбрасываются — зафиксировать это в docstring как известное ограничение или считать на неполных блоках; решение: считать только полные блоки, как прототип, чтобы приёмочные 71→88 % воспроизводились). Через `sat[:hb*B,:wb*B].reshape(hb,B,wb,B)` и `m.sum(axis=(1,3))` получается быстрый отбор; цикл только по отобранным блокам.

### Pattern 2: Сетка тайлов с приклеиванием остатка (D-07/D-08)
```python
def tile_edges(n: int, tile: int) -> List[Tuple[int, int]]:
    """Границы [a,b) вдоль оси; остаток < tile/2 приклеивается к последнему полному."""
    full, rem = divmod(n, tile)
    edges = [(i*tile, (i+1)*tile) for i in range(full)]
    if rem == 0: return edges
    if full == 0 or rem < tile/2:
        if edges: edges[-1] = (edges[-1][0], n)
        else: edges = [(0, n)]
    else: edges.append((full*tile, n))
    return edges
```
Тесты (табличные): `tile_edges(1600,256)` → 6 тайлов, последний `(1280,1600)` (320 px); `3840,256` → 15 ровно; `2160,256`: 8×256=2048, rem 112 < 128 → приклеен (последний 2048..2160 → (1792,2160)); `1080,256`: 4×256=1024, rem 56 → приклеен; `n<tile` → один тайл; rem ровно = tile/2 → отдельный тайл (граница «меньше половины»). Покрытие: сумма длин = n (инвариант-тест property-style). Чётность границ: tile чётный, `edges[-1]` заканчивается на n; для цветности — отдельный вызов с `tile//2` и размером плоскости цветности (не делить границы Y пополам, иначе при нечётном остатке разъезд). Для Y и UV считать сетки независимо; для «худшего тайла по цвету» тайлы UV индексируются в координатах цветности, а в json писать пиксельные координаты в Y-системе (×2).

### Pattern 3: PSNR через MSE и inf
`psnr(a,b)`: `mse = mean((a-b)^2)` в float64 из int32-разности (`a.astype(np.int32)-b`), `inf` при 0. Пик 1023 (10 бит). Худший тайл — минимальный PSNR, но по D-09 для цвета ранжировать по суммарному MSE U+V (не по PSNR каждого отдельно; тайлы UV одинаковой геометрии благодаря общей сетке).

### Pattern 4: ΔE ITP (D-12) — константы сверены
Источники: Dolby ICtCp whitepaper v7.1, Wikipedia ICtCp, ITU-R BT.2124-0 (три совпадающих набора). `[CITED: professional.dolby.com/siteassets/pdfs/ictcp_dolbywhitepaper_v071.pdf; itu.int BT.2124-0]`; поиск подтвердил числа независимо `[VERIFIED: web search, 2026-10-05]`; внутренние суммы строк локально проверены (строки LMS = 4096, строки Ct/Cp = 0 → серый даёт Ct=Cp=0).
Конвейер: код 10-бит limited → `Y=(y-64)/876`, `Cb=(u-512)/896`, `Cr=(v-512)/896` → BT.2020 NCL (Kr=0.2627, Kb=0.0593): `R=Y+2(1-Kr)Cr`, `B=Y+2(1-Kb)Cb`, `G=(Y-Kr R-Kb B)/(1-Kr-Kb)` — это ЗАГОЛОВОЧНЫЕ нелинейные R'G'B' (PQ), → линейные нормированные (0..1 = 0..10000 нит) через PQ EOTF (клип в [0,1]) → LMS:
```
L=(1688R+2146G+262B)/4096; M=(683R+2951G+462B)/4096; S=(99R+309G+3688B)/4096
L'M'S' = PQ inverse EOTF (OETF) of L,M,S
I  = 0.5L'+0.5M'
T  = 0.5*Ct = 0.5*(6610L'-13613M'+7003S')/4096
P  = (17933L'-17390M'-543S')/4096
ΔE_ITP = 720*sqrt(ΔI²+ΔT²+ΔP²)
```
Нюанс (важно для корректности): прямое EOTF→LMS→OETF — это «тонкая» цепочка; допустимо считать нелинейные R'G'B' → EOTF → линейные → LMS → OETF. Клипать R'G'B' в [0,1] после YCbCr→RGB (энкодерный шум даёт выход за гамму). Тесты: идентичные кадры → ΔE=0; серая плоскость vs серая плоскость с другим Y → ΔE>0 и симметрия `ΔE(a,b)==ΔE(b,a)`; нейтральный серый → Ct=Cp≈0 (проверка матрицы). Порог видимости ≈1 `[CITED: FEATURES.md/BT.2124]`.
Память: на 4K RGB float32 ≈ 74 МБ ×несколько временных → считать полосами по 128 строк (`for r0 in range(0,H,128)`), накапливая только вектор ΔE полосы (для p99 нужен весь массив ΔE float32: 3840×2160×4 = 33 МБ — приемлемо; либо подвыборка `[::2, ::2]`, решение за планировщиком, но с тестом, что результат стабилен). Чётный H/W: цветность апсемплить повтором (nearest, `np.repeat`) — зафиксировать как допущение (отражает прототип «границы чётные»).

### Pattern 5: Кандидаты и слияние (D-13..D-16)
`Candidate(frame:int, sources:Tuple[str,...], primary:str, scene:Optional[int])`.
Алгоритм `merge_candidates(manual, vmaf, csv, scan, min_gap, per_scene_quota, top, scenes)`:
1. Все входы — списки `(frame, source_tag, rank)`; приоритет `manual(0) < vmaf(1) < csv(2) < scan(3)`.
2. Ручные: безусловно включаются первыми (никогда не выбрасываются; в `top` считаются, но не вытесняются: если ручных > top — остаются все, лимит применяется к остальным).
3. Остальные по возрастанию приоритета источника, внутри — по рангу (худшие сначала), затем по номеру кадра (детерминизм). Кандидат, у которого есть выбранный ближе `min_gap`, НЕ добавляется как новый, а его источник дописывается в `sources` ближайшего выбранного (D-15 «список ВСЕХ источников»). Обработка: сначала составить итоговые кадры, затем второй проход «присоединить» отброшенных.
4. Квота на сцену: считать сколько выбрано в сцене (по `scenes`, bisect по `start`); ручные не расходуют/не нарушают квоту; если квота полна — новый кандидат тоже мёржится как источник в ближайшего той же сцены, не создаёт новый.
5. `top` — после квоты; возвращать отсортированно по кадру.
`min_gap`: расстояние `abs(a-b) < min_gap` — коллизия (прототип: `>= gap` допустимо; сохранить, граница `== min_gap` разрешена; закрепить тестом).
Сцена из `scenes: List[Tuple[int,int]]` через `bisect` на отсортированных началах.

### Pattern 6: Ридер CSV qsvencc (CND-02)
Формат (из `write_metrics_csv`): колонки `scene,start_frame,end_frame,frames,seek,trim,encode_sec,fps,size_mb,ssim_all,ssim_db,psnr_avg,ssim_y,psnr_y`; последняя строка `scene=ИТОГО` (пустые `start_frame/end_frame`); значения могут быть пустыми (None), `inf`, `nan` (csv пишет `inf`/`nan` как есть). Парсить `float()` в try; `ИТОГО` пропускать по `scene.strip()=="ИТОГО"` ИЛИ пустому `start_frame`. `start_frame/end_frame` — int; `end_frame` исключающий (как `.scenes` `[S,E)`); середина `start+(end-start)//2` всегда внутри сцены (для сцены в 1 кадр = start). Худшие по `ssim_y`: сортировка по возрастанию (меньше = хуже); по `psnr_y` — тоже возрастание, `inf`-значения (идентичные) в конец, `nan`/пусто исключить. Если у колонки нет ни одного конечного значения → `SourceStatus(unavailable, "колонка ssim_y пуста — метрики не считались")`. Сторож: round-trip через `write_metrics_csv` в `tmp_path` с inf/nan/None/ИТОГО (импорт `encoding.metrics` — только в тесте).

### Pattern 7: Ридер VMAF (CND-04)
Порт `read_vmaf` + проверки: (a) delimiter по вхождению `\t` в первых 4 КБ (как прототип; безопаснее — `csv.Sniffer` не нужен); (b) заголовок регистронезависимо, колонка `vmaf`; (c) десятичная запятая: `replace(",", ".")` — ТОЛЬКО если разделитель tab (в csv с запятой-разделителем десятичная запятая невозможна без кавычек; для csv значения с кавычками `"93,5"` csv.reader уже вернёт целую ячейку — replace тоже корректен); (d) база индекса: найти колонку кадра (`frame`, `frameNum`, `n`, `frame_num` — регистронезависимо), если есть и `first != 0` → отказ «база индекса 1 …»; если колонки кадра нет — индекс = номер строки с 0, база не проверяема (записать в статус «колонка кадра отсутствует, база индекса не проверена» как предупреждение, не отказ); (e) длина `len != expected` → отказ с обоими числами. Исключение `AnalysisError`/результат-тип: ридер возвращает `(values|None, SourceStatus)`; не бросает на плохих данных (паттерн `(result, err)`). Нечисловые значения (`nan`, пусто) → отказ с номером строки. Тест на строку заголовка с BOM (`utf-8-sig`) — открывать файл с `encoding="utf-8-sig"` в I/O-обёртке.
Формат libvmaf: `log_fmt=csv` даёт колонки `Frame,vmaf,...` с `Frame` от 0 `[ASSUMED]` — точных колонок реального вывода libvmaf в этой сессии не перепроверял; отсюда допущение (a-d) и тестовая фикстура с базой 1. (Netflix libvmaf, `--output --csv` поведение — сверить на реальном файле оператора, если появится.)

### Pattern 8: Модель отчёта и JSON (RPT-01, D-18..D-21)
Frozen dataclasses: `AnalysisReport(schema_version=1, meta, thresholds, sources, candidates, frames, summary)`. `Threshold(name, value, provisional=True)` — список строится из `AnalyzeConfig` через `dataclasses.fields`, чтобы ни один порог не забыли пометить (тест: каждое числовое поле конфига есть в `thresholds`, все `provisional`).
`to_jsonable(obj)`: рекурсивно: dataclass → dict (`dataclasses.asdict` либо ручной, но asdict глубоко копирует — норм), tuple→list, `float`: `isnan→None`, `+inf→"inf"`, `-inf→"-inf"`, numpy-скаляры → Python (`np.float32`→`float`, `np.int64`→`int`; без этого `json.dumps` падает). Затем `json.dumps(..., sort_keys=True, indent=2, ensure_ascii=False, allow_nan=False)` + завершающий `\n`. `allow_nan=False` — страховка, что нормализация не пропустила NaN. Округление чисел: чтобы golden не зависел от платформенной погрешности, в фикстуре использовать «круглые» значения; в продуктиве метрики округлять при записи в модель (например 4–6 знаков) — решить в `FrameMetrics` конструкторе-хелпере, не в `to_jsonable`.
Golden: `tests/unit/analysis/golden/report_v1.json` читать `read_bytes()` и сравнивать с `render_json(fixture_report).encode("utf-8")`. Обновление golden — только осознанно (флаг/комментарий в тесте), `schema_version` меняется только при несовместимости. Ключ `sort_keys` делает порядок независимым от порядка полей датакласса — но имена полей = ключи (D-18), значит переименование поля ломает golden (ожидаемо).
md/html: чистые функции `render_md(report)->str`, `render_html(report)->str`; `html.escape(name, quote=True)` для всех пользовательских строк (имя файла, причина отказа, источник); `<meta charset="utf-8">`; ссылки на PNG — поля `Optional`, в фазе 9 пустые. Метка «provisional» — отдельный блок «Пороги (provisional, не откалиброваны)» в md и html. Тест md/html — подстрока/структура, не байтовое равенство; html-тест на имя `a&b "x" <i>.mkv`.
Сводка перцентилей: `np.percentile(vals, [0,1,5,10,50])` на конечных значениях (inf/nan/None исключить, но записать `n`); при пустом наборе → `None`. Явно зафиксировать метод (по умолчанию `linear`) комментарием — golden от него зависит.

### Anti-Patterns to Avoid
- **`nan` как признак «нет деталей»:** прототип так делал; в модели — `status`+`None`.
- **Среднее отношений вместо отношения сумм** (B5) — используйте оба поля из D-02, ранжируйте по p10.
- **Ручное `% 1023`/клип проекции:** D-04 запрещает.
- **`die()`/`subprocess` в `analysis/`:** ридеры возвращают статус; `AnalysisError` только для программных ошибок (неверный dtype/форма).
- **Модульные глобалы `GRID_X/GRID_Y/CHROMA_B`:** только поля `AnalyzeConfig`.
- **`json.dumps` без нормализации:** `Infinity`/`NaN` не валидный JSON; numpy-скаляры сериализатор не знает.
- **`np.frombuffer` view в хранимых результатах** (B11): в модель кладутся только Python-числа.

## Don't Hand-Roll

| Problem | Don't Build | Use Instead | Why |
|---------|-------------|-------------|-----|
| CSV/tsv разбор, кавычки | split(",") | `csv.reader`/`DictReader` | кавычки, BOM, пустые строки |
| HTML-экранирование | replace('<'...) | `html.escape` | кавычки/амперсанды |
| JSON стабильность | ручной вывод | `json.dumps(sort_keys, indent, allow_nan=False)` | детерминизм, строгость |
| Перцентили | своя сортировка | `np.percentile` | фиксированный метод |
| Поиск сцены по кадру | линейный цикл | `bisect` по началам | O(log n), чёткие границы [S,E) |
| Глубокое копирование модели в dict | рекурсия руками | `dataclasses.asdict` + нормализатор | не забыть вложенные |

**Key insight:** сложность фазы — не в алгоритмах, а в числовых граничных случаях (inf/nan/None, край тайла, пустые наборы), поэтому таблицы тестов важнее реализации.

## Common Pitfalls

### Pitfall 1: Неверный диапазон/матрица в ΔE ITP
**What goes wrong:** full-range вместо limited или BT.709 вместо BT.2020 → систематический сдвиг ΔE.
**How to avoid:** константы в config (`LUMA_BLACK=64, LUMA_RANGE=876, CHROMA_MID=512, CHROMA_RANGE=896, KR=0.2627, KB=0.0593`); тест: Y=940,Cb=Cr=512 → R=G=B=1 → ~10000 нит и Ct=Cp=0.
**Warning signs:** ненулевой ΔE для серого с одинаковой яркостью.

### Pitfall 2: Деление на ноль/малый знаменатель
**What goes wrong:** `Σ(s·s)` = 0, `lap_energy(src)`≈0 (плоский источник) → inf/nan «сохранность детали».
**How to avoid:** `detail = lap(e)/max(lap(s), eps)` как в прототипе (eps=1e-9); для тайловой — тайлы с `lap(s) < eps` исключить из минимума (иначе минимум 0/0). Решение зафиксировать константой и тестом (плоский кадр → detail=None/1.0 по выбору, но документировано).

### Pitfall 3: Лапласиан на тайлах и краях
Лапласиан отрезает границу (1 пиксель) — на тайле размером 1×N вернёт пустой массив → `mean` пустого = nan + RuntimeWarning. Защитить: `if h<3 or w<3: return None`. Тайлы всегда ≥ tile/2 по построению, но тесты с крошечными кадрами (например 8×8) должны проходить: для 8×8 при tile=256 — один тайл на всё.

### Pitfall 4: uint16 арифметика
`a - b` на uint16 заворачивается (переполнение вниз). Всегда `astype(np.int32)` до вычитания (в прототипе так сделано в `diff_png`, а `psnr` использует float64 — корректно). Тест: пара где `a<b`.

### Pitfall 5: float32 против tол-ерантности
float32 для PQ степеней: `e**(1/m2)` с m2=78.84 даёт ошибку ~1e-6; для ниток <5 порог — нормально; тесты опорных кодов с `rel=1e-3` (или считать PQ в float64 на малых массивах, а в тяжёлом ITP — float32 с допуском ΔE ±0.01). Планировщику: сначала float64 везде + полосы; оптимизировать только при замере (по Discretion).

### Pitfall 6: Нечётные размеры плоскостей цветности
4:2:0 при нечётных W/H даёт `ceil`. Для 10-бит HDR реальные размеры чётные; на входе `analyze_frame` проверять `u.shape == (ceil(h/2), ceil(w/2))` и бросать `AnalysisError` при несоответствии (программная ошибка вызывающего).

### Pitfall 7: Недетерминированное слияние
Сортировка без второго ключа при равных рангах (одинаковый vmaf) даёт нестабильный порядок → golden/тесты флапают. Всегда ключ `(priority, rank, frame)`.

### Pitfall 8: Ручные кадры и квота
Ручной кадр, попавший в сцену, не должен уменьшать квоту автоматических до 0 при сравнении с «квота=2»: определить правило — ручные не расходуют квоту (рекомендовано, подтверждается D-15 «никогда не выбрасываются»); зафиксировать тестом.
