    Функции этой задачи:
    - `tile_edges(n, tile)` — алгоритм RESEARCH Pattern 2: `full, rem = divmod(n, tile)`; rem==0 → ровные тайлы; `full == 0` → `[(0, n)]`; `rem < tile / 2` → последний полный тайл растягивается до n; иначе отдельный тайл `(full*tile, n)` (граница «ровно половина» → отдельный тайл, D-08). n <= 0 или tile <= 0 → AnalysisError.
    - Приватный `_strips(n, rows)` → `[(r, min(r + rows, n)) for r in range(0, n, rows)]` — единственный нарезчик полос модуля (используют mse, lap_energy, luminance_stats, delta_e_itp).
    - `mse(a, b)` — по полосам `_strips(H, ITP_STRIP_ROWS)`: в полосе разность `a.astype(np.int64) - b.astype(np.int64)` (защита от заворота uint16, Pitfall 4), сумма квадратов `int((d * d).sum())` копится в Python int (точно; переполнения int64 в полосе нет: 65535² · 128 · 3840 ≈ 2·10¹⁵), результат `total / (H*W)` как `float`. int32 (предложение review OpenCode) НЕ используется: квадрат разности uint16 вне 10-битного диапазона переполняет int32, а полосы и так снимают пик памяти.
    - `psnr(a, b)` — `inf` при mse == 0, иначе `10*log10(PEAK_10BIT**2 / mse)`; приватный хелпер `_psnr_from_mse(m)` переиспользуется тайлами.
