## Сводка

Проверен пакет `src/enpipe/analysis/` (конфиг, метрики, ридеры источников, слияние кандидатов, модель и рендеры отчёта) и быстрый тир `tests/unit/analysis/`. Тесты проходят (274 passed), ruff чист, проверка конвенций (`verify conventions`) замечаний не дала: правила есть только для JS/TS, Python пропускается.

Константы стандартов совпадают с BT.2020, BT.2100, BT.2124 и ST 2084: коэффициенты YCbCr→R'G'B', матрицы RGB→LMS и LMS→ICtCp /4096, константы PQ m1/m2/c1..c3, множитель 720 при T=0.5·Ct. Полосовой расчёт и целочисленные MSE и лапласиан корректны. Блокеров не найдено.

Главные проблемы находятся в ридерах. Нарушен заявленный контракт «parse_* никогда не бросают». CSV метрик тихо теряет строки сцен и пропускает перевёрнутые и отрицательные диапазоны, из-за чего появляется кандидат с отрицательным номером кадра. Повреждённый `.scenes` тихо отключает квоту. Кроме того, у ΔE ITP нет проверки цветовых (Ct/Cp) строк матриц: требование D-12 «сверить по стандарту» закреплено только серыми тестами. Все находки ниже подтверждены прогоном (scratchpad-скрипт), если не сказано иное.

## Warnings

### WR-01: `parse_frames` бросает ValueError, хотя по контракту не бросает никогда

**Файл:** `src/enpipe/analysis/sources.py:46,75-76`
**Проблема:** `_FRAMES_ITEM_RE` пропускает `\d+` неограниченной длины, а `int()` в Python 3.12 отказывается разбирать строку длиннее 4300 цифр (`sys.int_info.str_digits_check_threshold`). Вызов `parse_frames("9"*5000, cfg)` проверен: он бросает `ValueError` вместо `SourceStatus(REJECTED)`. Модульный docstring (строки 4-7) обещает, что `parse_*` «никогда не бросают исключений». В фазе 10+ строку пользователя `--frames` уронит трейсбеком, а не отказом источника.
**Исправление:** ограничить длину числа в regex или поймать ошибку:
```python
_FRAMES_ITEM_RE = re.compile(r"\s*(\d{1,12})\s*(?:-\s*(\d{1,12})\s*)?")
```
либо обернуть `int(...)` в `try/except ValueError` с тем же `STATE_REJECTED`. Нужен также тест на сверхдлинное число.

### WR-02: CSV метрик молча выбрасывает строку сцены с пустым `start_frame`

**Файл:** `src/enpipe/analysis/sources.py:166-169`
**Проблема:** условие `if scene_cell == _CSV_TOTAL or not start_cell: continue` нужно, чтобы пропускать `ИТОГО`. Но оно же без следа пропускает любую строку сцены с пустым `start_frame`, даже если в ней есть `ssim_y`/`psnr_y`. Проверено: строка `2,,,0.1,1` (худшая сцена файла) исчезает, а статус остаётся `enabled` без notes. Пустые строки целиком `DictReader` и так не отдаёт, так что в этом условии нет нужды. Это противоречит духу D-14 «источник сообщает, не падает и не молчит».
**Исправление:** пропускать только `ИТОГО`. Строку с пустыми `start_frame`/`end_frame` отвергать (через тот же `ValueError` → `STATE_REJECTED` с номером строки) или хотя бы считать в `notes`:
```python
if scene_cell == _CSV_TOTAL:
    continue
```

### WR-03: CSV принимает перевёрнутые и отрицательные границы, кандидат получает отрицательный кадр

**Файл:** `src/enpipe/analysis/sources.py:170-179, 231`
**Проблема:** `start_frame`/`end_frame` никак не проверяются. Проверено: строка `1,-10,-4,...` даёт `RawCandidate(frame=-7)`, строка `0,100,50,...` даёт кадр 75, то есть кадр за пределами `[S, E)`. Эти кадры дойдут до извлечения в фазе 10. Повреждённый CSV должен быть отвергнут, а не превращаться в кандидата.
**Исправление:** после разбора строки проверять `0 <= start_frame < end_frame` и при нарушении возвращать `STATE_REJECTED` с номером строки (`f"CSV метрик: строка {line}: границы [{s}, {e}) некорректны"`).

### WR-04: нечитаемый или битый `.scenes` тихо отключает квоту на сцену

**Файл:** `src/enpipe/analysis/sources.py:113-118`
**Проблема:** `read_scenes_file` превращает `OSError`/`UnicodeDecodeError` в `[]`. Пустой результат `parse_scenes` (файл есть, но формат не тот) тоже даёт `[]`. В `merge_candidates` пустой список означает «квоты нет» (D-16). Получается, что существующий, но повреждённый `.scenes` меняет состав кандидатов, и это нигде не отражается: нет ни `SourceStatus`, ни notes. Все остальные ридеры отдают статус, а этот нет.
**Исправление:** возвращать `Tuple[List[Tuple[int,int]], Optional[str]]` (или `SourceStatus`-подобную заметку). Различать «нет файла», «нечитаем» и «0 сцен в существующем файле» и выводить предупреждение в отчёт.

### WR-05: `AnalyzeConfig` не проверяет `chroma_sat_thr`, отсюда ZeroDivisionError в `small_chroma`

**Файл:** `src/enpipe/analysis/config.py:94-115`, `src/enpipe/analysis/metrics.py:434,437`
**Проблема:** комментарий `# > 0: все точки маски насыщены` верен только при `chroma_sat_thr >= 0`. Проверено: при `AnalyzeConfig(chroma_sat_thr=-1, chroma_max_pts=256)` и серой цветности (точки с s=0 попадают в маску) получаем `ZeroDivisionError: float division by zero` вместо `AnalysisError`. Порог объявлен калибруемым (D-05, фаза 13), так что такой конфиг правдоподобен. Ещё одна недоработка: `chroma_max_pts > chroma_block**2` молча делает верхнюю границу бессмысленной.
**Исправление:**
```python
if not self.chroma_sat_thr >= 0:  # ловит и nan
    raise AnalysisError("chroma_sat_thr должен быть >= 0")
```
В `small_chroma` дополнительно пропускать блок, если `ss == 0`.

### WR-06: время в отчёте показывает «0:60.00»

**Файл:** `src/enpipe/analysis/report.py:501-504`
**Проблема:** `f"{int(sec // 60)}:{sec % 60:05.2f}"` округляет секунды отдельно от минут. Проверено: `_time_text(59.999)` возвращает `0:60.00`, а `_time_text(119.996)` возвращает `1:60.00`. Это неверная отметка времени в md/html, которой оператор пользуется, чтобы найти кадр в плеере.
**Исправление:** сначала округлить до сотых, потом делить:
```python
cs = round(sec * 100)
return f"{cs // 6000}:{(cs % 6000) / 100:05.2f}"
```

### WR-07: тесты ΔE ITP не проверяют цветовые строки матриц (Ct/Cp) и коэффициенты Cb/Cr

**Файл:** `tests/unit/analysis/test_itp.py:29-83`
**Проблема:** все опорные тесты серые (Cb=Cr=512). На сером входе LMS = RGB, а T и P равны нулю при любой ошибке в строках 2-3 `LMS_TO_ICTCP`, если их сумма равна нулю. Ошибка в `KR`/`KB` или в формулах `r`/`b`/`g` (`metrics.py:490-492`) тоже не обнаружится. Остальные тесты (симметрия, `p99 >= mean`, полосы против целого кадра) самосогласованные. D-12 прямо требует сверки констант со стандартом, но закрепления в тестах нет. Сейчас константы верны (проверено вручную), но регрессию никто не поймает.
**Исправление:** добавить табличный тест на 2-3 насыщенных цветах с независимыми опорными значениями. Например, чистый BT.2020 красный, зелёный и синий на 100 нит в коде 10-bit с ICtCp, посчитанными внешней реализацией (colour-science) и вписанными литералами. Плюс тест ΔE между двумя цветами с известным ΔE ITP из BT.2124.

## Info

### IN-01: лимит `max_frames_range` считается до дедупликации

**Файл:** `src/enpipe/analysis/sources.py:83-84`
**Проблема:** `0-9999,0-9999` (10000 уникальных кадров) отвергается как 20000. Для защиты от DoS это безопасно, но текст причины («20000 кадров») вводит в заблуждение.
**Исправление:** назвать величину честно («суммарная длина диапазонов 20000») или считать объединение интервалов.

### IN-02: висячая запятая в `--frames` отвергает весь список

**Файл:** `src/enpipe/analysis/sources.py:67-74`
**Проблема:** `"100,"` и `"100,,200"` дают `STATE_REJECTED` с причиной `некорректный элемент «»`. Обычная опечатка выключает ручной источник целиком, хотя ручные кадры по D-15 самые приоритетные.
**Исправление:** пропускать пустые элементы (`if not item.strip(): continue`) или назвать причину понятно («пустой элемент»).

### IN-03: VMAF-CSV с разделителем `;` отвергается как «нет колонки vmaf»

**Файл:** `src/enpipe/analysis/sources.py:277`
**Проблема:** разделитель выбирается только из `\t` и `,`. В русской локали CSV с десятичной запятой почти всегда пишется через `;`. Такой файл отвергается громко, но с ложной причиной «нет колонки vmaf».
**Исправление:** добавить `;` в кандидаты (`csv.Sniffer` с `delimiters="\t;,"`) или хотя бы указывать в причине, что заголовок прочитан одной колонкой.

### IN-04: `Candidate.scene` — индекс в отсортированном списке, а не номер сцены из файла

**Файл:** `src/enpipe/analysis/sources.py:103-110`, `src/enpipe/analysis/candidates.py:424-432,465,520`
**Проблема:** `parse_scenes` отбрасывает `scene NNNN`, и `scene_of` возвращает позицию в `sorted(scenes)`. Это совпадает с номером сцены (`Scene.index`, колонка `scene` в CSV) только для полного, непрерывного `.scenes`. Для частичного файла или файла с дубликатами номера в отчёте разойдутся с CSV.
**Исправление:** сохранять номер сцены из строки (расширить regex на `scene\s+(\d+)`) и возвращать его из `scene_of`; при этом обновить тест-сторож на совпадение с `encoding.scenes_io._SCENE_RE`.

### IN-05: в `csv_candidates` дубликаты номера сцены сливаются молча

**Файл:** `src/enpipe/analysis/sources.py:216-237`
**Проблема:** ключ `picked` равен `s.scene`. Две строки CSV с одним `scene` и разными границами схлопываются в кадр первой, а вторая худшая сцена теряется.
**Исправление:** отвергать CSV с повторяющимся `scene` в `parse_metrics_csv` или использовать ключ `(scene, start_frame)`.

### IN-06: незащищённое содержимое из входных файлов в report.md, сквозной `to_jsonable` для неизвестных типов

**Файл:** `src/enpipe/analysis/report.py:493-494,627,290-313`
**Проблема:** (а) `_md_cell` экранирует только `|` и переводы строк. Текст причин, в который попадает содержимое ячеек VMAF/CSV (`«{cell}»`), и имена файлов внутри inline-кода (`` `{value}` ``) попадают в md без экранирования, так что бэктик в имени файла ломает разметку, а сырой HTML уходит в md-просмотрщик. (б) `to_jsonable` возвращает неизвестные типы как есть (`np.ndarray`, `Path`), и `json.dumps` упадёт `TypeError` уже при записи отчёта, а не в месте ошибки.
**Исправление:** (а) экранировать `` ` ``, `<`, `>` в `_md_cell` или выводить мета-значения без inline-кода. (б) в конце `to_jsonable` бросать `AnalysisError(f"не сериализуемый тип {type(obj).__name__}")`.
