## Предупреждения

### WR-07: docstring `_taken_frames` и комментарий теста утверждают, что «сдвигать повтор некуда» на всём диапазоне; это верно только до n = 197

**Файл:** `src/enpipe/analysis/pair.py:168-169`, `tests/unit/analysis/test_pair.py:522`

**Проблема:** docstring говорит про весь диапазон «49..225, 241, 289»:
«Каждый повтор попадает в окрестность какой-либо из пяти целей, сдвигать
повтор некуда». Первая часть верна. Вторая неверна. В UAT оператор ограничил её
явно: «до ~200 кадров окрестности покрывают весь файл — сдвигать некуда».
Расчёт по `_taken_frames(pick_points(n, None, 0, CFG), CFG)`:

```
n ≤ 197 : окрестности покрывают [0, n) целиком
n = 200 : свободны 25, 75, 174
n = 225 : цели [0, 56, 112, 168, 224]; свободны 25..31, 81..87, 137..143, 193..199 (28 кадров)
n = 241 : свободны 44 кадра (25..35, 85..95, 145..155, 205..215)
n = 289 : свободны 92 кадра
```

Комментарий теста `test_pair.py:522` тоже неверен: «n=225: цели [0, 56, 112,
168, 224], окрестность ±24 покрывает весь файл». Пример: при n = 225 повтор 48
цели 0 попадает в окрестность цели 56 (32..80). Вариант (а) сдвинул бы его на
81, и этот кадр свободен. Значит, на 198..225, 241 и 289 повторы пропадают из-за
выбора «пропускать, а не сдвигать», а не из-за геометрии. Поведение и вердикт
это не ломает: решение (б) принято оператором осознанно, и его здесь не
оспариваю. Но задача гэпа 10-10 по 10-HUMAN-UAT — «масштаб описан верно». Сейчас
текст опять оправдывает ограничение неверным доводом. Если к варианту (а)
вернутся при калибровке, фраза «сдвигать некуда» подскажет, что он бесполезен,
хотя на 198..289 он вернул бы повторы.

**Исправление:** поправить только текст.

```python
    файла). До ~197 кадров окрестности целей покрывают весь файл — сдвигать
    повтор некуда; на 198..225, 241 и 289 свободные кадры есть, повторы
    пропадают из-за пропуска (а не сдвига) — решение оператора.
```

В тесте:

```python
# n=225: цели [0, 56, 112, 168, 224]; каждый повтор (48, 96, 104, 144, 152,
# 160, 200, 208, 216) лежит в окрестности ±24 какой-либо цели;
```

## Замечания

### IN-10: масштаб 49..225 в docstring верен только без .scenes, но это не сказано (новое, 10-10)

**Файл:** `src/enpipe/analysis/pair.py:165-168`, `src/enpipe/analysis/align.py:276`

**Проблема:** docstring говорит «При дефолтах (±24, шаг 48) повторы D-11 не
выполняются ни на одном энкоде 49..225 кадров … Каждый повтор попадает в
окрестность какой-либо из пяти целей». С `.scenes` это неверно. Обычные цели
(склейка уже занята другой целью) повторы получают: `_point_worker` проверяет
только `target.junction`. Расположение целей и занятых кадров зависит от
склеек. Пример: n = 192, `scenes=[(0,152),(152,192)]`. Цели: 0 (склейка),
48, 152 (склейка), 143, 191. Повтор 96 цели 48 разрешён. На 20 000 случайных
раскладок (n из 49..225, 1..6 склеек) разрешённые повторы нашлись в 1207
случаях. Docstring `align.retry_frames` («повторных попыток точки без .scenes»)
тоже вводит в заблуждение: повторы бывают и при `.scenes`, если цель не стала
склейкой. Вердикт не страдает, потому что ошибка в консервативную сторону.

**Исправление:** в `_taken_frames` уточнить «без .scenes (пять обычных целей)»
и добавить «с .scenes зависит от раскладки склеек». В `retry_frames` написать
«повторы обычной (не склеечной) точки».

### IN-11: граничный тест повторяет условие пропуска у себя и не проверяет `_point_worker` (новое, 10-10)

**Файл:** `tests/unit/analysis/test_pair.py:508-539`

**Проблема:** `_allowed_retries` сама воспроизводит строки 211-213
`_point_worker` (`if f in taken: continue`) и фильтр склеек не применяет. При
`scenes=None` это не нужно. Если воркер начнёт сдвигать повторы (вариант (а))
или поменяет условие, `test_retries_allowed_boundary` останется зелёным.
Docstring при этом утверждает «Граница закреплена test_retries_allowed_boundary».
Через воркер сейчас идёт только `test_static_121_retries_skipped`, одна длина.
Кроме того, `if n == 226: assert len(got) >= 1` после `assert got == expected`
ничего не проверяет. Диапазон «49..225» целиком тоже не закреплён, хотя прогон
всего диапазона дешёвый.

**Исправление:** для 225 и 226 проверить через `check_pair_files` на
`static_film(n)` и класс `Fake`, какие кадры энкода запрошены:

```python
@pytest.mark.parametrize("n, retries", [(225, []), (226, [144, 200])])
def test_retries_boundary_via_worker(fake, n, retries):
    f = fake({SRC: static_film(n), ENC: static_film(n)})
    pair.check_pair_files(SRC, ENC, CFG)
    targets = [t.enc_frame for t in align.pick_points(n, None, 0, CFG)]
    assert sorted(c[1] for c in f.calls if c[0] == ENC) == sorted(targets + retries)
```

Плюс `assert all(not _allowed_retries(n) for n in range(49, 226))`. Лишнюю
проверку для 226 убрать.

### IN-03: `offset_hints` пропускает диапазон после сцены нулевой длины (без изменений)

### IN-09: критерий независимости голосов неявно зависит от шага повтора (без изменений)

**Исправление:** вынести разнос в отдельное provisional-поле
`align_vote_sep` с проверкой `2·align_window ≤ align_vote_sep <
align_retry_step`.
