## Замечания

### IN-14: «Без .scenes каждый повтор попадает в окрестность какой-либо цели» сказано без ограничения по длине (новое, 10-12)

**Файл:** `src/enpipe/analysis/pair.py:168-169`

**Проблема:** в формулировке, которую предлагал IN-12, было «каждый повтор **на
этих длинах** попадает в окрестность». В 3cf1ef2 уточнение выпало, и
предложение стало отдельным: «Без .scenes каждый повтор попадает в окрестность
какой-либо цели». Так оно не верно. Перебор n ∈ 49..599 без `.scenes` на
настоящих `pick_points` / `retry_frames` / `_taken_frames` даёт 372 длины из 551
(первая — 226), на которых есть повторы вне всех окрестностей. Тест
`test_retries_boundary_via_worker[226]` закрепляет именно такой случай (повторы
144 и 200). Из предыдущего предложения понятно, о каких длинах речь, но
ошибка того же рода, что в WR-07, IN-10 и IN-12: утверждение, верное для части
случаев, подано как общее. На поведение не влияет.

**Исправление:** только текст.

```python
    вообще (первый повтор 48 за концом файла). На этих длинах без .scenes
    каждый повтор попадает в окрестность какой-либо цели. При n ≤ 197
```

### IN-15: «Числа закреплены тестами» обещает больше, чем проверяют тесты (новое, 10-12)

**Файл:** `src/enpipe/analysis/pair.py:176-179`, `tests/unit/analysis/test_pair.py:508-513`

**Проблема:** раньше концовка была «Граница закреплена
test_retries_boundary_via_worker», теперь это «Числа закреплены тестами: …».
Но два числовых утверждения того же docstring ни один тест не проверяет:
- «при n ≤ 197 окрестности покрывают весь файл» (первый свободный кадр при
  n=198);
- «свободные кадры есть (на 225 их 28, на 241 — 44, на 289 — 92)».

Если поменять `pick_points` или `vote_separation`, эти числа устареют без
падения тестов. Те же числа повторяет комментарий над граничным тестом
(`test_pair.py:510-512`). Именно эти утверждения исправлялись в WR-07. На
поведение не влияет.

**Исправление:** выбрать одно из двух.
- Сузить текст: «Диапазон и пример закреплены тестами: …».
- Или добавить дешёвый перебор:

```python
def test_taken_coverage_numbers():
    def free(n):
        t = align.pick_points(n, None, 0, CFG)
        tk = pair._taken_frames(t, CFG)
        return sum(1 for f in range(n) if f not in tk)
    assert all(free(n) == 0 for n in range(1, 198))
    assert free(198) > 0
    assert (free(225), free(241), free(289)) == (28, 44, 92)
```

### IN-03: `offset_hints` пропускает диапазон после сцены нулевой длины (без изменений)

**Файл:** `src/enpipe/analysis/precheck.py:102-110`

**Проблема:** окно с `lens[lo] == 0` отбрасывается целиком. Примеры
`[(0,0),(0,5)]` и `[(0,3),(3,3),(3,8)]` при `n_enc = 5` дают пустые подсказки.

**Исправление:** перед проверкой границ сделать
`while lo < hi and lens[lo] == 0: lo += 1`. Добавить оба случая в тест.

### IN-04: `UnicodeDecodeError` выходит из `check_pair_files` (без изменений)

**Файл:** `src/enpipe/analysis/frames.py:100`, `src/enpipe/analysis/pair.py:280-285`

**Проблема:** ffprobe запускается с `text=True` без `errors=`, а цикл probe
ловит только `AnalysisError`. Байты не в UTF-8 вызывают исключение, которое
уходит к вызывающему.

**Исправление:** передавать `errors="replace"` в `_proc.run`.

### IN-07: замер jobs в scratch-скрипте обрывается на первой ошибке точки (без изменений)

### IN-09: критерий независимости голосов неявно зависит от шага повтора (без изменений)

**Файл:** `src/enpipe/analysis/align.py:166-178`, `src/enpipe/analysis/config.py:126-132`

**Проблема:** `vote_separation = max(2W, align_retry_step // 2)`. Если при
калибровке поднять `align_retry_step`, вместе с ним незаметно вырастут разнос
голосов и окрестность запрета повторов. Новые тесты 10-12 это частично
страхуют: уменьшение разноса ловит `test_retries_absent_whole_range`,
увеличение — граница 226 (см. мутации в сводке). Сама связь параметров
остаётся неявной.

**Исправление:** вынести разнос в отдельное provisional-поле
`align_vote_sep` с проверкой `2·align_window ≤ align_vote_sep <
align_retry_step`.
