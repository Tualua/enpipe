## Предупреждения

### WR-08: с `.scenes` статичный кадр 0 даёт отказ там, где без `.scenes` файл выровнен (новое, 10-13)

**Файл:** `src/enpipe/analysis/pair.py:204-213`, `pair.py:237-245`, `src/enpipe/analysis/align.py:222-224`

**Проблема:** при `.scenes` первая цель всегда склейка 0: `pick_points` тянет
t=0 к склейке 0, а с `--offset` по D-07 кадр 0 энкода — тоже начало сцены.
Склейка 0 меряется одним кадром (`pair.py:204`) и повторов D-11 не получает.
Её спасает только замена. До 10-13 «неопределённая» склейка 0 не мешала: хватало
двух голосов. По (в) она стала фатальной, если свободной склейки-замены нет.

Зонд через `check_pair_files` с `Fake`, `noisy_film(1000)`, кадры 0..29
статичны (≈ 1,25 с):

| `.scenes` | Вердикт | Кадры ENC |
|---|---|---|
| нет | **выровнено** (повтор 48) | `[0, 48, 250, 500, 749, 999]` |
| `[(0, 1000)]` | **отказ**, «неопределённые точки (кадры энкода): 0» | `[0, 250, 500, 749, 999]` |
| `[(0, 500), (500, 1000)]` | **отказ**, точка 0 | `[0, 250, 499, 749, 999]` (кандидат 500 — цель, в taken) |

Это не ложное «выровнено», а отказ, поэтому не BLOCKER. Но:
- поведение зависит от того, передан ли `.scenes`, и с ним проверка строже.
  Обычно `.scenes` есть всегда: его пишет сам enpipe;
- сильнее всего страдает частичный энкод ALN-04 из одной-двух сцен
  (`--from/--to` по сценам, `--offset K`). Там кандидатов-замен нет вовсе, и
  на кадре 0 достаточно ничьей d=0 / d=+1 (запас < 3 дБ) в спокойном плане;
- следствие (в) из 10-13-SUMMARY, «отказ дают статичное начало длиннее зоны
  повторов вперёд (≈ 6 с)», верно только без `.scenes`. С `.scenes` хватает
  одного неразличимого кадра 0, если замен нет. Пункт «статичная склейка, у
  которой все кандидаты … исчерпаны» формально этот случай покрывает, но про
  то, что кандидатов может не быть совсем, там не сказано.

Решения оператора «склейке — замена склейкой» это не противоречит: что
делать, когда замен нет, оператор не решал.

**Исправление:** нужно решение оператора, отдельным вопросом. Варианты:
- (1) когда `junction_replacements` пуст или все замены «неопределённо»,
  проверять склейку как обычную точку по `align.retry_frames(target.enc_frame,
  n, cfg, taken)`. Повторы одиночными кадрами, тот же общий лимит;
- (2) оставить как есть и явно записать в docstring `_point_worker` и в
  SUMMARY: «с .scenes склейка 0 без свободных соседних склеек при
  «неопределённо» даёт отказ; без .scenes та же пара может быть выровнена».
  Добавить тест-якорь (две строки из таблицы выше).

```python
        if target.junction:
            for rep in align.junction_replacements(target, junctions, taken, cfg):
                ...
            # вариант (1), только по решению оператора:
            for f in align.retry_frames(target.enc_frame, len(enc_pts), cfg, taken):
                again = _measure(src, enc, src_pts, enc_pts, [f], offset, width, height, cfg, None)[0]
                if again.verdict != ALIGN_UNDETERMINED:
                    return again, None
            return point, None
```

**Проблема:** `vote_separation = max(2W, align_retry_step // 2)`. Если при
калибровке поднять `align_retry_step`, вместе с ним незаметно вырастут разнос
голосов, окрестность taken, а после 10-13 и величина сдвига повторов и набор
допустимых замен склеек (1б, 2б). Тесты 10-13 с точными списками кадров
(`test_retries_via_worker`, `test_junction_replacements_rules`) такой дрейф
поймают, но сама связь параметров остаётся неявной.

**Исправление:** вынести разнос в отдельное provisional-поле
`align_vote_sep` с проверкой `2·align_window ≤ align_vote_sep <
align_retry_step`.
