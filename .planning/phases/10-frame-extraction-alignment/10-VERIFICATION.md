### Независимое подтверждение находок ревью

- **CR-01 — ПОДТВЕРЖДЁН.** По коду: `retry_frames`/`_point_worker` не исключают занятые кадры, `aggregate` не дедуплицирует. Запуск `align.aggregate` с точками `[24 undet, 48 aligned, 48 aligned, 95 undet]` вернул `verdict=aligned, n_aligned=2` при `align_min_aligned=2`. То есть защита D-13 обходится, файл признаётся выровненным по одному кадру. Это тихий неверный результат на малоподвижном материале, прямо противоречащий формулировке «громкий отказ при любом сомнении» и ALN-03. Классификация: BLOCKER. Регрессионного теста нет (в `test_pair.py` проверка `n_aligned == 4` только для случая без пересечений). Фикс малый и локальный.
- **WR-01 — ПОДТВЕРЖДЁН** (охранное условие `grab_frame_pair` не смотрит `check.ok`). Вызывающих в `src/` сейчас нет, поэтому на поведении CLI не сказывается, но нарушает контракт «до метрик пара проверена» для будущего потребителя (фаза 11). Классификация: BLOCKER для ALN-02 как контракта API, дёшево исправляется вместе с CR-01. Если оператор решит отложить на фазу 11 — это его решение, но фаза 11 должна явно закрыть.
- **WR-02 — ПОДТВЕРЖДЁН как риск, не как воспроизведённый дефект.** Таблица строится по пакетам, `grab_frames` проверяет лишь число байт, декодированные pts не сверяются. Для n=0 `-ss` не задаётся. Случай RASL-кадров открытой GOP-нарезки на реальных данных не воспроизводился. Классификация: WARNING (unverifiable_runtime), требует решения оператора.
- **WR-03 — ПОДТВЕРЖДЁН** (воркер ловит `AnalysisError, OSError, ValueError`). Другое исключение прерывает всю проверку громко, а не молча: результат не подменяется, поэтому на цель «громкий отказ» не влияет, лишь теряет диагностику остальных точек. Классификация: WARNING.
- IN-01..IN-05, CV-01: не блокируют цель; IN-01 (`verdict.ok == True` у отвергнутой выравниванием пары) — родственный риск для потребителя, рекомендуется чинить вместе с WR-01.
