<objective>
Чистое ядро решений фазы 10: вердикт выравнивания (точка, склейка, кадр, файл), выбор точек, предпроверка пары и правила `--offset`. Всё — функции без I/O, subprocess и numpy, с табличными юнит-тестами.

Purpose: вся логика «отказ при любом сомнении» тестируется быстро и без ffmpeg; I/O-слой (10-03) и оркестратор (10-04) только поставляют данные.

Зафиксированные решения планировщика (Claude's Discretion / ASSUMED из RESEARCH, записать в SUMMARY):
- Метрика сходства — PSNR Y полного кадра (`metrics.psnr`); в `align.py` приходят уже готовые числа (модуль без numpy).
- Склейка (A5): сравниваются кадры энкода `start−1` и `start`; «выровнено» — если оба выровнены, «сдвиг» — если любой сдвинут, иначе «неопределённо»; для start = 0 — только `start`.
- Если склеек меньше `align_points`, недостающие точки добираются равномерными (с повторами D-11) — иначе энкод из одной сцены отвергался бы всегда.
- Ошибка извлечения в точке — причина отказа (D-13 «отказ при любом сомнении»), а не «неопределённо».
- Число кадров — длина таблицы pts, не тег `nb_frames`; допуск fps — относительный `fps_rel_tol` (24000/1001 и 24/1 различаются).
- Пустой список сцен (нет/нечитаемый `.scenes` — `read_scenes_file` возвращает []) трактуется как «`.scenes` нет».
- DV fail-loud (открытый вопрос 2): side data DOVI есть, а профиль не прочитан → отказ «профиль Dolby Vision не определён». A6 закрыт реальными данными оператора (10-DV-P5-PROBE.json, ffprobe n9.0.2, For.All.Mankind S01E01, mp4, HEVC Main 10, codec_tag dvhe): `side_data_type = "DOVI configuration record"`, `dv_profile` — целое 5; у P5 НЕТ ключей color_space/color_transfer/color_primaries (только color_range=tv). Поэтому на P5 `check_pair` выдаёт и DV-причину, и несовпадения тегов, и «не PQ»; DV-причины ставятся первыми (корень), остальные — следствия, не подавляются.
- Чересстрочный вход (замечание ревью, принято как отказ): `field_order` не None и ≠ "progressive" у источника или энкода → причина отказа. Почему отказ, а не пометка: энкод enpipe прогрессивный, сравнение полей с кадрами не определено, а неопределённость = отказ (D-13, D-20). None (ffprobe не знает) — прогрессивный, иначе ложные отказы на mkv без флага.
- Отрицательные pts (замечание ревью): `min(pts) < 0` → причина в `pts_reasons` — поведение `-ss` с отрицательной целью и `-seek_timestamp 1` не проверено, «отказ при любом сомнении».

Учтённые замечания кросс-ревью (10-REVIEWS.md, Consensus 1–2):
- `pick_points`: целочисленные цели вместо float + `round()` (банковское округление давало бы флипы на половинах при points ≠ 5); тесты points=6, половинный случай и 3 точки на несимметричных сценах (0,10),(10,20),(20,96).
- `point_verdict`: ключ сортировки и правило ничьей формализованы (см. truths), тест симметричных ±1.
- Известное ограничение (OpenCode, MEDIUM): склейки НЕ получают повторных точек (D-11 описывает повторы только для случая без `.scenes`); при ≥ 3 малоподвижных склейках файл получит «неопределённо» → отказ без попытки соседней точки. Сейчас не реализуется (вне решений CONTEXT; калибровка — фаза 13); место оставлено: `AlignTarget` — frozen-датакласс, будущее поле повтора добавляется последним с дефолтом без правки вызывающих, а решение «повторять или нет» принимается в одном месте (`_point_worker` 10-04 по `target.junction`). Записать в 10-02-SUMMARY раздел «Известные ограничения».
- `combine_junction`: в docstring явно — `margin_db` результата = минимум определённых (не None) запасов; если определённых нет — None.
