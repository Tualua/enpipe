<objective>
Одночанковый режим для источников без pts (повод — quick 261112-dab: `wmv3` в ASF, у всех видеопакетов `pts_time=N/A`, ffprobe-фолбэк таблицы ключевых кадров пуст, номера по dts уходят от вывода декодера на +2/+3). Такой источник кодируется целиком одним вызовом `qsvencc --avsw` без `--seek`/`--trim` и без детекта сцен; число кадров выхода сверяется с полным программным декодом источника; режим объявляется в логе.

Решения оператора (2026-11-12, заблокированы): (1) один вызов qsvencc `--avsw` на весь файл; (2) включение по факту отсутствия pts у видеопакетов, для любого кодека; (3) детекта нет, главы mkv — из источника, `.metrics.csv` — одна строка + ИТОГО; (4) кадры выхода = кадры полного декода источника, иначе `die()`; (5) явная строка лога; (6) план после 10.1-11, UAT 10.1-12 после этого плана; (7) отказ `decode.py` для `wmv3` заменяется этим режимом для источников без pts, `vc1image` не решён (вопрос в 10.1-11 Task 1); (8) сценовая нарезка таких источников — бэклог 999.8; (9) исправить утверждение о главах в CLAUDE.md.

Purpose: WMV9 и подобные источники без pts сейчас падают на таблице ключевых кадров. Одночанковый режим кодирует их корректно (без краёв чанков — нечему сдвигаться) и громко сообщает, что сцен нет.
Output: модуль `single_chunk.py`, ветка в `run_encode` и `_pipeline_one`, громкий отказ фолбэка при ключевых кадрах без pts, сквозной аппаратный тест на куске wmv3, исправленный CLAUDE.md.

Определение «нет pts» (выбор планировщика по решению 2, обоснование).
- Проверка двухступенчатая, только демультиплексирование, без декода. Ступень 1: `ffprobe -select_streams v:0 -read_intervals %+#1000 -show_entries packet=pts_time`. Если среди прочитанных пакетов есть хоть один с числовым pts, у источника pts есть, ответ готов (обычные источники — десятки мс). Ступень 2 запускается, только если все прочитанные пакеты без pts: тот же запрос по всему файлу. «Нет pts» — ровно когда pts нет у ВСЕХ видеопакетов файла (N > 0). Ноль видеопакетов, ненулевой rc ffprobe, нечисловое и не `N/A` значение дают `die()`.
- Замеры планировщика (2026-11-12): кусок wmv3 (ASF) — 2996 из 2996 пакетов без pts; полный `wmv_test4.wmv` — 43399 из 43399, полный проход 1.06 с. Кусок VC-1 в mkv (Fringe) — 358 из 717 без pts, все 31 ключевой пакет без pts, но 2-й пакет с pts. Поэтому VC-1 после ступени 1 идёт прежним путём, и это правильно: его таблица — из Cues, доказано на B50 (10.1-10).
- Частичные pts: правило «все/не все» не пускает их молча в одночанковый режим, а на сценовом пути закрывается дыра фолбэка. Таблица ключевых кадров берётся либо из Cues (не зависит от pts пакетов), либо из пакетов. Во втором случае каждый ключевой пакет обязан иметь pts. Сейчас `keyframe_table_ffprobe` молча пропускает ключевые пакеты с `N/A`; после плана это громкий отказ. Неключевые пакеты без pts (бывает в MPEG-TS) таблицу не портят и поведение не меняют.

Как сочетаются отказ `decode.py` и режим (решение 7 → план):
- Порядок в `_pipeline_one` и `run_encode`: решение о декоде (строка `декод:`), затем `probe_pts`. Если pts нет — одночанковый режим, `refuse_unsafe_avsw` не вызывается: отказ касается краёв `--seek/--trim`, которых здесь нет. Это относится к любому кодеку без pts, в том числе к `vc1image` (решение 2: «любой такой источник»). Вопрос 10.1-11 о `vc1image` касается только сценового пути.
- `wmv3` с pts (например, в mkv/avi) идёт сценовым путём и получает громкий отказ `refuse_unsafe_avsw`: `wmv3` остаётся в `AVSW_UNSAFE_CODECS` после 10.1-11 при любом ответе (см. примечание оркестратора в 10.1-11). Края его чанков не измерены. Ответ выводится из решения 7 («для источников без pts»), отдельный вопрос оператору не нужен. В текст отказа добавляется, что одночанковый режим включается только у источников без pts.
- Одночанковый режим требует `choice.path == "sw"` (решение 1: `--avsw`). Источник без pts с решением `hw` (явный `--decode hw` или auto для аппаратного кодека) — `die()` с подсказкой `--decode sw`. Строка `декод:` уже напечатана, молча менять путь нельзя (D-01).
