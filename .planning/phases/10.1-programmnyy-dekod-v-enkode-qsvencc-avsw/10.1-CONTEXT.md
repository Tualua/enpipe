# Phase 10.1: Программный декод в энкоде (qsvencc --avsw) - Context

**Gathered:** 2026-11-11
**Status:** Ready for planning

<domain>
## Phase Boundary

enpipe кодирует источники, кодек которых текущая GPU не декодирует аппаратно (повод — VC-1 Fringe S02 на Arc B50: vainfo без VC-1, qsvencc rc 225, ffmpeg `vc1_qsv` — ошибка). Для таких файлов чанки идут через `qsvencc --avsw` (программный декод + аппаратный AV1-энкод), детект сцен — через программный декод ffmpeg. Инварианты корректности сохраняются: seek/trim по ключевым кадрам, сверка числа кадров на чанк и на весь `movie.obu`, keyframe-выравнивание чанков, детект сцен.

Вне фазы: кодирование чересстрочного видео (деинтерлейс/bob/IVTC), замена энкодера, смена дефолтов JOBS, изменения анализа (`src/enpipe/analysis/`).

</domain>

<decisions>
## Implementation Decisions

### Выбор пути декода
- **D-01:** Авто-выбор плюс флаг-переопределение. В режиме auto путь решается **один раз на файл до первого чанка** и одинаков для всех чанков файла; без пробных запусков и отката по коду ошибки.
- **D-02:** Список аппаратно декодируемых кодеков спрашивается у qsvencc при запуске (кандидат — `qsvencc --check-features`; исследователь подтверждает, что вывод содержит секцию декодеров и её формат на r4677 / B50). Кодек источника — из ffprobe (`codec_name`). Кодек не из списка → `--avsw`, из списка → `--avhw` (как сейчас).
- **D-14 (решено оператором 2026-11-11, уточняет D-02):** ключ выбора — `(кодек, цветность, разрядность)` из `codec_name` + `pix_fmt` источника против ячейки таблицы `Supported Decode features` (в ячейке — максимальная разрядность). Пример: H.264 на B50 только 8 бит 4:2:0 → Hi10P AVC идёт на `--avsw`. Неизвестный/неразбираемый `pix_fmt` в режиме auto — громкий отказ с подсказкой `--decode hw|sw` (как D-04).
- **D-03:** Флаг `--decode auto|hw|sw`, по умолчанию `auto`, в `encode`, `run` и `detect`. `hw` = принудительно `--avhw` / QSV-декод в детекте, `sw` = принудительно `--avsw` / программный декод в детекте. — **Reversibility:** costly — флаг CLI попадает в скрипты и cron оператора.
- **D-04:** Если в режиме auto опрос декодеров не сработал или вывод не разобрался — громкий отказ (`die()`) до детекта и первого чанка с подсказкой «задайте `--decode hw` или `--decode sw`». Ни догадки, ни вшитого запасного списка. При явном `--decode hw|sw` опрос не нужен.

### Детект сцен
- **D-05:** Одно решение на весь файл: `--decode` управляет и детектом, и энкодом. В auto VC-1 детектируется программным декодом (`use_qsv=False`, как сейчас `--no-qsv`) и кодируется с `--avsw`. В `enpipe run` решение принимается один раз и передаётся в обе стадии.
- **D-06:** `--no-qsv` в `detect` и `run` остаётся синонимом `--decode sw`, в `--help` помечен как устаревший. `--no-qsv` вместе с `--decode hw` — ошибка (взаимоисключение).
- **D-07:** Чересстрочный источник — громкий отказ **на любом пути** (`--avhw` и `--avsw`) до детекта, с объяснением, что кодирование чересстрочного видео не поддерживается. Это сознательное расширение: сейчас такой файл тихо уходит в AV1 с «гребёнкой». — **Reversibility:** reversible.
  - **D-13 (решено оператором 2026-11-11, после исследования):** отказ только на явных `tt/bb/tb/bt`. Отсутствующий ключ `field_order` (`-of json`) и значение `unknown` считаются прогрессивом — так ffprobe n9.0.2 отдаёт все просмотренные HEVC/AV1 mkv (RESEARCH.md, раздел «field_order: доказательства»). Аналог существующей политики анализа `src/enpipe/analysis/precheck.py:350`. Покадровой пробы нет. Известное ограничение: чересстрочный файл без флага в контейнере не будет пойман.

### Проверка корректности
- **D-08:** Два уровня автотестов:
  1. синтетический HEVC Main10 (как текущие тест-исходники) с принудительным `--decode sw` — механика чанков на `--avsw`;
  2. hardware-тест (маркер `hardware`) на коротком куске реального VC-1 (Fringe), нарезанном `mkvmerge` без перекодирования. Путь к куску — через переменную окружения; без неё тест — skip. Кусок в репозиторий не кладётся.
- **D-09:** Критерий корректности чанка на `--avsw`: число кадров чанка = длина сцены, и первый/последний кадр чанка соответствуют кадрам S и E−1 источника (на синтетике — номер кадра в картинке или ближайший PSNR среди соседних кадров). Ловит сдвиг seek/trim на один кадр. Существующие сверки числа кадров в пайплайне сохраняются как есть.
- **D-10:** Приёмка (UAT): оператор **сам** запускает `enpipe run` на Fringe S02E01 (в UAT — готовая команда, без python-однострочников). Ожидаемо: в логе строка выбранного декода `sw`, все чанки прошли сверку числа кадров, mkv собран; итог проверяется `ffprobe`/`mkvmerge` (число кадров, длительность).

### Нагрузка на CPU и отчёт
- **D-11:** JOBS и потоки декода не менять. Исполнитель замеряет скорость и загрузку CPU на куске VC-1 при JOBS 1/2/3 и записывает цифры в SUMMARY; дефолт меняется только отдельным решением оператора.
- **D-12:** Выбранный путь декода — одна строка в логе до детекта, с причиной, например: «декод: sw (vc1 нет среди аппаратных декодеров GPU; --decode auto)». Формат `.metrics.csv` и итоговый mkv не меняются.

### Унаследовано (не переобсуждалось)
- Корректность важнее всего: при сомнении — громкий отказ, не тихий проход (PROJECT.md Core Value).
- Баг qsvencc на пути `--avsw` → handoff-документ в форк Tualua/QSVEnc и громкий отказ в enpipe до фикса (память проекта «Баги qsvencc → handoff»).
- `--backend qsv` остаётся явным (`src/enpipe/encoding/chunk.py:27-33`); меняется только `--avhw` ↔ `--avsw`.
- Гейт версии qsvencc (`ensure_qsvencc_fixed`, r4677) не меняется; r4665 уже включает фикс RADL для `--avsw`.

### Claude's Discretion
- Где жить решению о декоде (модуль/функция) и как оно передаётся в `chunk_command` и `DetectionConfig` — на усмотрение планировщика, в рамках конвенций (`die()` на главном потоке, subprocess только через `enpipe.shared.proc`).
- Точная формулировка строки лога и текста отказов (на русском).

</decisions>

<code_context>
## Existing Code Insights

### Reusable Assets
- `chunk_command(...)` — единственное место сборки argv qsvencc; переключение `--avhw`/`--avsw` локально здесь.
- `DetectionConfig.use_qsv` + `QsvPipeStream` — программный декод детекта уже есть (`--no-qsv`), нужен только авто-выбор.
- `probe_source` (`detection/stream.py:27`) и `probe_fps` (`encoding/pipeline.py:95`) — ffprobe-обёртки; `codec_name`/`field_order` можно получать рядом.
- `parse_revision` / `ensure_qsvencc_fixed` — образец «спросить qsvencc и громко отказать при непонятном выводе» для опроса декодеров.
- Харнесс `tests/integration/_chunk_content.py` — сверка содержимого чанков.

### Established Patterns
- Preflight до любой долгой работы (which + гейт версии) — опрос декодеров и проверка field_order встают туда же.
- `die()` только на главном потоке; воркеры возвращают `(ok, err)`.
- Все subprocess — через `enpipe.shared.proc`; тесты мокают через pytest-subprocess.
- Hardware-тесты исключены по умолчанию, запускаются `-m hardware`.

### Integration Points
- `cli/main.py`: аргументы `--decode` в `detect`/`encode`/`run`, синоним `--no-qsv`, взаимоисключение.
- `run_pipeline` (`cli/main.py`): одно решение о декоде на файл, передаётся в детект и энкод (и в батч-режиме — на каждый файл отдельно).
- `run_encode` (`encoding/pipeline.py`): решение о декоде перед циклом чанков, строка лога D-12.

</code_context>

## Specific Ideas

- Целевой материал: `/data/downloads/temp/Fringe.COMPLETE.SERIES.1080p.REMUX-FraMeSToR/Fringe.S02.BluRay.1080p.DD.5.1.VC-1.REMUX-FraMeSToR/Fringe.S02E01.A.New.Day.in.the.Old.Town.1080p.DD.5.1.VC-1.REMUX-FraMeSToR.mkv` — 1080p, 23.976 к/с, прогрессив по ffprobe, ≈44 мин, AC3 5.1, 5 дорожек PGS.
- Для B50 ожидаемый набор аппаратных декодеров: h264, hevc, av1, vp9, mpeg2 (без VC-1) — проверяется опросом, а не вшивается.
- `qsvencc --avsw [<string>]` принимает необязательное имя декодера (из `qsvencc --help`).
- В UAT — готовые команды; без `python -c` (память проекта).

</specifics>
